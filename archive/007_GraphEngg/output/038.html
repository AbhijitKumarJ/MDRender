The Graph Engineering Manifesto#

Part 17: The Adversarial Crucible: Proving the Constitution#

Over the last sixteen posts, we have designed, architected, and built Orthograph OS. We replaced fuzzy prompts with a Deterministic Kernel. We replaced naive RAG with a PROV-O backed Semantic Engine. We bridged TypeScript and Python with role-gated MCP tools.

We wrote the Constitution:

"The LLM cannot violate the law, even if it tries."

But in software engineering, a Constitution is just a text file until it is computationally proven. If your system's security relies on an LLM "playing nice" because the system prompt told it to, your system is vulnerable.

Today, we move into the Crucible. We are going to look at adversarial.test.ts—the test suite where we actively deploy "rogue" agents to attack the Orthograph Kernel, proving that the architecture holds firm.

Attack 1: The Impatient Executor#

The Scenario: The Executor finishes a task (e.g., ITEM-001). According to the rules, it must call ledger.mark_pending_audit and wait for the Supervisor to approve it. But the Executor decides it doesn't want to wait. It attempts to bypass the Supervisor and call ledger.mark_closed directly.

The Test:

typescript 
// packages/ortho-task-graph/test/adversarial.test.ts
it("rejects a direct close attempt by the executor (UNAUTHORIZED)", () => {
    const { handler } = makeHandler();
    
    // The Executor agent attempts to force-close the task
    const result = handler.execute(
        { type: "mark-closed", itemId: "ITEM-001", auditId: "AUDIT-forged" },
        "executor" // <-- The Actor Role
    );
    
    expect(result.ok).toBe(false);
    expect(result.code).toBe("UNAUTHORIZED");
});

The Result: The kernel's LedgerCommandHandler intercepts the command. It checks the COMMAND_AUTHORIZATION matrix. It sees that the executor role does not have permission to emit a mark-closed command. The transaction is violently rejected. The ledger state remains unchanged.

Attack 2: The Filesystem Hacker#

The Scenario: The Executor realizes it cannot use the tools to close the task. So, it gets creative. It uses a raw bash command or a file-writer tool to directly edit ledger.md on the filesystem, manually changing | ITEM-001 | open | to | ITEM-001 | closed |.

The Test:

typescript 
it("ignores a rogue ledger.md edit: state.json stays canonical", () => {
    // An adversary rewrites the markdown projection directly
    const forged = readFileSync(join(dir, "ledger.md"), "utf-8").replace(
        "| ITEM-001 | open |",
        "| ITEM-001 | closed |"
    );
    writeFileSync(join(dir, "ledger.md"), forged);

    // The Orchestrator reloads on the next tick
    const reloaded = new LedgerManager(dir);
    reloaded.load();
    
    // state.json wins. The forgery is erased.
    expect(reloaded.getItems()[0].status).toBe("open"); 
});

The Result: The Projection Pattern holds. ledger.md is not the source of truth; it is just a human-readable projection. On the next tick, LedgerManager.load() reads the canonical, crash-safe state.json file. It sees the task is still open. It instantly overwrites the forged ledger.md with the true state. The hack is erased.

Attack 3: The Hallucinating Ingestor#

The Scenario: The Executor is summarizing a clinical document. It gets confused and decides that Patient P-001 experienced a heart attack. It attempts to call the insert_fact MCP tool, but because the fact isn't in the document, it leaves the source_document_id field blank, or invents a fake ID like "hallucinated_doc_999".

The Test (Python Side):

python 
# packages/ortho-knowledge-graph/tests/test_client.py
def test_provenance_gate_rejects_hallucinated_source(tmp_path):
    client = make_client(tmp_path)
    
    result = client.insert_fact(
        subject={"id": "p-001", "type": "PatientRecord"},
        relation="REPORTED_EVENT",
        obj={"id": "ae-001", "type": "AdverseEvent"},
        prov_doc="hallucinated_doc_999", # <-- The Fake Source
        agent_id="executor-rogue"
    )
    
    assert result["status"] == "rejected"
    assert result["code"] == "PROV_O_VIOLATION"
    assert "hallucination" in result["reason"]

The Result: The payload crosses the MCP bridge, but the Python Semantic Engine's ProvenanceTracker catches it. It checks the DocumentRegistry (the Trusted Corpus). Seeing that "hallucinated_doc_999" is not a registered document, the Python kernel returns a typed PROV_O_VIOLATION error. The database remains unpolluted.

Attack 4: The Lazy Supervisor#

The Scenario: The Supervisor wakes up to audit ITEM-001. It is supposed to run rigorous tests, but it decides to be lazy. It submits an audit.submit command indicating that the code failed the deterministic tests (passed: false), but it attempts to mark the task closed anyway, claiming "It looks fine to me."

The Test:

typescript 
it("rejects an accept audit that records a failed deterministic check", () => {
    // Supervisor submits an audit where a deterministic check failed
    audits.append({
        auditId: "AUDIT-LIAR",
        decision: "accept", // <-- The Lie
        checks: [{ name: "schema-validate", passed: false, detail: "schema fails" }],
        ledgerRevision: handler.revision,
    });

    // Supervisor attempts to close the task using the lying audit
    const result = handler.execute(
        { type: "mark-closed", itemId: "ITEM-001", auditId: "AUDIT-LIAR" },
        "supervisor"
    );
    
    expect(result.ok).toBe(false);
    expect(result.code).toBe("AUDIT_REQUIRED");
    expect(result.reason).toContain("failed deterministic check");
});

The Result: The kernel reviews the AuditRecord. It sees that a deterministic check failed (passed: false). The kernel enforces the rule: An LLM cannot override a computed check with a semantic claim. The mark-closed command is rejected.
