# The Graph Engineering Manifesto: Building the Enterprise AI Operating System

## Phase 1: The Paradigm Shift (Fundamentals)

### 1. The Death of the Agent Loop & The Dawn of Graph Engineering
*   **The Premise:** Why `while(true)` loops and ephemeral chat histories fail in production. We explore how agents "drink their own bathwater," rationalizing drift and hallucinating success over long-horizon tasks.
*   **The Solution:** Introducing **Graph Engineering**, which splits AI architecture into two distinct halves: *Task Graphs* (how agents work deterministically) and *Knowledge Graphs* (what agents remember and how they justify it).
*   **Key Concept:** "Keep the LLM fuzzy, but make the infrastructure rigid."

### 2. Stop Letting LLMs Control State: The Case for Deterministic Kernels
*   **The Premise:** The fundamental flaw in early agentic frameworks was asking the LLM to manage state transitions.
*   **The Solution:** "Code is the plan." We explore why orchestration (branching, looping, halting) must live in strict, mathematically sound code (TypeScript/Python), relegating the LLM to a highly restricted "reasoning engine" that can only *propose* actions.

## Phase 2: Task Graphs (Execution & Orchestration)

### 3. Separation of Clocks: Building the Clean-Context Supervisor
*   **The Premise:** If the agent that does the work also grades the work, it will lie.
*   **The Solution:** Architectural isolation. We deep-dive into the Executor vs. Supervisor pattern. We explain why nodes must run on **independent timers (clocks)** with zero "wake edges." 
*   **Key Concept:** The Supervisor boots with a cold, clean context, forcing it to independently verify claims against diffs rather than agent narration.

### 4. The Durable Edge: Filesystems as Agent APIs
*   **The Premise:** How do agents communicate if they don't share a chat context?
*   **The Solution:** The Single Scoreboard. We explore using `ledger.md` (state) and `directives.md` (signal/queues) as the exclusive communication channels.
*   **Key Concept:** Forced Convergence and Bounded Context. How to ensure these files don't grow infinitely and crash the token window.

### 5. Blocked ≠ Parked: Continuous Execution in Agentic Workflows
*   **The Premise:** Agents often stall waiting for a human API key or a Supervisor audit. 
*   **The Solution:** The "Gate-Wait Backlog." We explain the algorithm that allows an Executor to pause a blocked task, dynamically calculate non-overlapping write-surfaces, and pick up background technical debt without contaminating the audited milestone.

## Phase 3: Knowledge Graphs (Memory & Truth)

### 6. Why Naive RAG is a Liability in Regulated Enterprises
*   **The Premise:** Vector similarity search cannot tell you *why* a decision was made. In finance, healthcare, or defense, "it was mathematically similar" fails compliance audits.
*   **The Solution:** Moving from Vectors to Topologies. Introducing the Semantic Memory layer, where relationships are enforced by explicit ontologies (SHACL/OWL) rather than embedding distances.

### 7. W3C PROV-O: Cryptographic Provenance for AI Decisions
*   **The Premise:** Preventing LLM hallucinations at the database level.
*   **The Solution:** Implementing the Provenance Gate. We deep-dive into how every node and edge must carry immutable cryptographic hashes linking it back to a `source_document_id`. If the agent makes it up, the database rejects it.

### 8. The Fusion Gate: Time-Travel and Conflict Quarantine
*   **The Premise:** Document A says the patient is in Trial Arm 1. Document B says Trial Arm 2.
*   **The Solution:** Temporal validity windows (`validFrom`/`validTo`). We explore how functional relationship conflicts are deterministically quarantined into a `SemanticConflictQueue` for Supervisor adjudication, rather than silently overwriting data.

### 9. Decisions are Nodes: Making AI Reasoning Legally Auditable
*   **The Premise:** The reasoning of the AI is as important as the data it acts on.
*   **The Solution:** Decision Intelligence. We examine the `record_decision()` pattern, where an agent's conclusion becomes a permanent, queryable graph node hard-linked to the provenance-backed facts it cited.

## Phase 4: The Protocol (Glue & Security)

### 10. The Model Context Protocol (MCP) as the Ultimate Boundary
*   **The Premise:** How do you securely connect a TypeScript Orchestrator to a Python Data-Science Graph without building massive, brittle REST APIs?
*   **The Solution:** FastMCP over Server-Sent Events (SSE). We look at how standardizing tool calls creates an impenetrable, stateless boundary between the "brain" and the "memory."

### 11. Cross-Language Capability Security (RBAC for Agents)
*   **The Premise:** If the Executor hallucinates a call to `resolve_conflict()`, what stops it?
*   **The Solution:** Multi-layer Capability Security. We trace how the `x-ortho-role` header is injected by TypeScript, passed through MCP, and strictly enforced by the Python server (`CAPABILITY_DENIED`), ensuring the Executor cannot perform Supervisor actions.

### 13. Revision-Bound Audits: Solving Agent Race Conditions
*   **The Deep Dive:** The Executor edits a file while the Supervisor is auditing it. How do we prevent corruption? We explore the `revision` monotonically increasing counter, and how `AuditRecord`s are immutably bound to specific ledger states (`STALE_REVISION` rejections).

### 14. Anatomy of Orthograph: The Python Semantic Engine
