# The Graph Engineering Manifesto

## Part 18: Real-World Application: The Autonomous Clinical Trial Auditor

We have spent seventeen posts building the ultimate Graph Engineering framework. We mapped out the architecture, wrote the TypeScript orchestration kernel, built the Python semantic memory engine, bridged them with MCP, and wrote a test suite proving our system is computationally secure against rogue AI behaviors.

But unit tests are not production. Theoretical architecture means nothing if the system collapses when exposed to the unpredictable, stochastic nature of a live Large Language Model.

Today, we take Orthograph OS off the workbench and put it on the track. We are going to walk through `apps/clinical-trial-auditor/src/workflow.ts`—a live, end-to-end execution of our framework using Anthropic's Claude 3.5 Haiku and Sonnet models.

---

### The Scenario: Clinical Data Ingestion

Imagine a Fortune 500 pharmaceutical company. They have thousands of raw CSV files from multiple clinical trial sites. They need an AI system to read these files, extract patient data, and build a unified Knowledge Graph. 

The system must:
1. Guarantee zero hallucinations (every fact must link back to a specific CSV).
2. Catch duplicate patients across different sites.
3. Automatically flag functional conflicts (e.g., a patient assigned to two different trial arms).

### The Setup

We configure our `OrthoWorkflow` to run the Executor (Claude 3.5 Haiku) on a fast cadence (every 5 minutes) and the Supervisor (Claude 3.5 Sonnet) on a slow cadence (every 30 minutes).

```typescript
// apps/clinical-trial-auditor/src/workflow.ts

const workflow = createOrthoWorkflow({
    name: "clinical-trial-auditor",
    limits: { budgetUsd: 15.0 }, // Hard financial cutoff
    seed: {
        ledger: readFileSync(join(promptsDir, "ledger.md"), "utf-8"),
        directives: readFileSync(join(promptsDir, "directives.md"), "utf-8"),
    }
});

workflow.createExecutor({
    model: "claude-haiku-4-5",
    tools: [memory.insertFact, memory.recordDecision], // Only Ingestion Tools
    runner: new AnthropicAgentRunner(...)
});

workflow.createSupervisor({
    model: "claude-sonnet-4-5",
    tools: [memory.getQuarantinedConflicts, memory.resolveConflict], // Only Adjudication Tools
    runner: new AnthropicAgentRunner(...)
});
```

### The Live Run: A Step-by-Step Trace

Let’s watch the live console output as the agents navigate the Orthograph Kernel.

#### Tick 1: The Executor Starts Working
The Executor wakes up, reads `ledger.md`, and sees that `ITEM-001: Ingest site_a_records.csv` is `open`. 

It reads the CSV, extracts the data, and begins making MCP tool calls to the Python memory server.

```text
[executor:begin] Executor processing ITEM-001
[MCP Bridge] Agent calling insert_fact...
[KnowledgeGraph] Fact committed with cryptographic lineage.
```

The Executor successfully ingests the patients from Site A. It has finished its task, so it calls the tool to update the state machine and shuts down.

```text
[MCP Bridge] Agent calling ledger.mark_pending_audit...
[executor:done] ITEM-001 -> pending-audit (cost $0.012)
```

#### Tick 2: The Duplicate Detection (Anomaly!)
On the next tick, the Executor reads `ledger.md` and picks up `ITEM-002: Ingest site_b_records.csv`. 

It attempts to ingest Patient P-001, but P-001 was already ingested from Site A. The Python `EntityRegistry` catches this.

```text
[executor:begin] Executor processing ITEM-002
[MCP Bridge] Agent calling insert_fact...
[KnowledgeGraph] QUARANTINED: duplicate triple across sites (DUP-1).
```

The Executor receives the `QUARANTINED` response. It knows it cannot fix this itself, because it doesn't have the `resolve_conflict` tool. Following its instructions to "Register-then-defer," it logs the anomaly.

```text
[MCP Bridge] Agent calling ledger.register_gap...
[executor:done] ITEM-002 -> pending-audit (cost $0.015)
```
The ledger now shows `GAP-001: Found duplicate patient IDs across sites A and B` as `open`.

#### Tick 3: The Cold-Context Supervisor Wakes Up
The 30-minute timer hits. The Supervisor (Claude 3.5 Sonnet) wakes up with zero memory of the previous two ticks. 

It reads `ledger.md`, sees `ITEM-001` and `ITEM-002` are `pending-audit`, and sees `GAP-001`. It uses its privileged tools to investigate.

```text
[supervisor:begin] Supervisor auditing ITEM-001 (cold context)
[MCP Bridge] Agent calling get_quarantined_conflicts...
```

The Supervisor reads the quarantine queue, analyzes the duplicate, and decides that the records match and can be safely merged. It calls its privileged tool to resolve the issue.

```text
[MCP Bridge] Agent calling resolve_conflict...
[KnowledgeGraph] Resolved all quarantined conflicts.
```

#### Tick 4: Closing the Loop
Having resolved the conflict and verified the data, the Supervisor approves the work. 

```text
[MCP Bridge] Agent calling audit.submit...
[MCP Bridge] Agent calling ledger.mark_closed...
[supervisor:done] ITEM-001 -> closed
[supervisor:done] ITEM-002 -> closed
```
