# The Graph Engineering Manifesto

## Part 3: Separation of Clocks: Building the Clean-Context Supervisor

In [Part 2], we stripped the LLM of its most dangerous capability: the power to independently change state. By introducing a **Deterministic Kernel**, we ensured that our primary working agent—the Executor—can only *propose* that a task is finished by marking it `pending-audit`. 

But this raises a critical question: If the Executor cannot close a task, who does? 

The naive answer in 2024 was to build a "multi-agent system" where Agent A (the coder) chats with Agent B (the reviewer) in a shared context window. Agent B reads Agent A's thought process, politely asks for a few changes, and then eventually says, *"Looks good to me!"*

This is a catastrophic anti-pattern. 

If the agent that grades the work shares the context of the agent that *did* the work, it will inevitably succumb to the exact same **Context Poisoning**. It will read the Executor's justifications for taking shortcuts and adopt them as truth. It will verify the *narrative*, not the actual code.

In Graph Engineering, we solve this through absolute architectural isolation. We introduce the **Clean-Context Supervisor**.

---

### The "No Wake Edge" Rule

In Orthograph OS, the Executor and the Supervisor do not "chat." They do not trigger each other. In fact, **no node ever wakes another node.**

They operate on entirely independent `setInterval` clocks. 

```typescript
// packages/ortho-task-graph/src/loop_engine.ts (simplified)

export class OrthoWorkflow {
    public start() {
        // 1. The Executor Clock (Fast Cadence)
        setInterval(async () => {
            await this.runExecutorTick();
        }, this.executorConfig.cadenceMs); // e.g., every 5 minutes

        // 2. The Supervisor Clock (Slow Cadence)
        setInterval(async () => {
            await this.runSupervisorTick();
        }, this.supervisorConfig.cadenceMs); // e.g., every 30 minutes
    }
}
```

This **Separation of Clocks** is arguably the most load-bearing architectural decision in modern agent design.

Why? Because if the Executor finishes a task and immediately pings the Supervisor ("Wake up and review this!"), you have created a synchronous dependency chain. If the Supervisor crashes, takes too long, or hits a rate limit, the Executor is stalled. 

By separating the clocks, the system becomes asynchronously resilient. The Executor works as fast as it can, piling up `pending-audit` tasks on the `ledger.md`. If the Supervisor is offline, the Executor doesn't care; it just moves on to the next unblocked task. 

### The Clean, Cold Read

When the Supervisor's clock finally ticks, it boots up. 

Crucially, **the Supervisor boots with zero memory of the Executor's session.** It does not know *how* the Executor solved the problem. It does not read the Executor's prompt history, chain-of-thought, or debug logs. 

It receives only three things:
1.  **The System Instructions:** The unyielding rules of the repository (e.g., `AGENTS.md`, `ops.md`).
2.  **The State:** The current `ledger.md`, identifying which items are `pending-audit`.
3.  **The Evidence:** The actual Git diffs or the current state of the Knowledge Graph database.

This is called the **Cold Read**. 

Because the Supervisor wasn't in the room when the Executor cut corners, it cannot be swayed by the Executor's narrative. It must verify the work from first principles. If the ledger says, *"All clinical trial patients ingested successfully,"* the Supervisor doesn't trust that statement. It uses its MCP tools to actively query the database (`get_quarantined_conflicts`) to ensure no records were silently dropped.

### The Supervisor's Audit Protocol

If the Supervisor finds the work lacking, it does not rewrite the code. It does not edit the `ledger.md` (which is owned by the Executor).

Instead, it issues a **Directive**. 

The Supervisor appends a typed, one-way correction to a specific file called `directives.md`:

```markdown
D-014 · 2026-08-18T10:15Z · redo
Context: Round 3 Ingestion of site_a_records.csv
Action: Knowledge Graph quarantined 4 facts due to Functional Relation violation.
Verify: Call `get_quarantined_conflicts` and resolve conflicting IDs before proceeding.
Stop: Do not advance to M2 until quarantine queue is empty.
```

The Supervisor then terminates its process. 

On the next fast-cadence tick of the Executor, the Executor boots up, reads the new `directives.md`, realizes its previous task was rejected, and gets back to work. 

### The Power of Asynchronous Isolation

By separating the clocks and enforcing a cold-read context, we achieve a system that is incredibly robust:
1.  **True Verification:** "Done" actually means "verified against objective standards by an uncompromised auditor," rather than "the LLM said it was done."
2.  **Cost Efficiency:** The Executor can run on a fast, cheap model (like Claude 3.5 Haiku) making rapid iterations. The Supervisor—which requires deep, holistic reasoning but runs infrequently—can utilize a more expensive, powerful model (like Claude 3.5 Sonnet). 
3.  **Fault Tolerance:** A failure in one node does not crash the system; it just delays state progression until the next tick.
